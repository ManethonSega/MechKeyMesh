# R9: Universal macro engine

Status: software implementation in validation.

## Scope

R9 creates the vendor-neutral macro domain before any keyboard write exists.

Events:

- `KeyDown`
- `KeyUp`
- `MouseDown`
- `MouseUp`
- `Delay`

Playback concepts represented by the model:

- once
- fixed repeat
- repeat while held
- toggle
- release to stop

Only `Once` is exposed in the R9 editor. The other concepts remain model-only until R10 has reliable F108 packet evidence and physical validation.

## Editor

The desktop editor supports:

- key and mouse recording inside an explicit capture area
- stop
- event insertion
- deletion
- one-event reorder
- direct delay editing
- event duplication
- event copy/paste
- macro rename
- macro duplication
- JSON import/export
- safe simulation

Recording generates explicit delay events between captured input events. Browser control clicks are outside the capture area and are not recorded.

## Persistence

The existing schema-2 `macros` and `macro_events` tables are now active.

Saving a macro performs one SQLite transaction:

1. validate the complete model
2. upsert macro metadata
3. delete the previous event list
4. insert the complete new ordered event list
5. commit

An interrupted or invalid save cannot leave a partial event sequence.

## Safety boundary

R9 exposes no macro method on `DeviceSession`, sends no HID report and does not advertise the driver `Macros` capability.

Simulation returns a timeline with:

```text
hardwareTouched = false
```

This makes the exit criterion testable without connecting an F108.

## Automated coverage

- all five event families serialize through the shared model
- all required playback concepts are representable
- zero keyboard usage is rejected
- repeat count zero is rejected
- excessive software delay is rejected
- explicit delays generate deterministic simulation timestamps
- macro metadata and ordered events survive database reopen
- replacing an event list is transactional
- deleting a macro cascades to its events
- wrong persistence capability is rejected
- frontend JavaScript syntax is checked in CI

## Evidence boundary

R9 proves local creation, editing, persistence and simulation only. It makes no statement about F108 macro slots, event encoding, delay limits, playback encodings or persistence in keyboard memory. Those are R10 responsibilities.
