# R10: F108 hardware macros

Status: software implementation complete; physical verification pending.

## Primary protocol evidence

Implementation is based on the reverse-engineered OEM sender and buffer format documented at commit `f7782b02e254490d9c4ae063a8c27cae38be226f` of `parsiya/f108-pro`:

- [`macro-protocol.md`](https://github.com/parsiya/f108-pro/blob/f7782b02e254490d9c4ae063a8c27cae38be226f/ai-docs/macro-protocol.md)
- [`key-remap-protocol.md`](https://github.com/parsiya/f108-pro/blob/f7782b02e254490d9c4ae063a8c27cae38be226f/ai-docs/key-remap-protocol.md)

That source explicitly says macro upload was documented but never tried. MechKeyMesh therefore exposes the implementation as unverified and does not claim the physical exit criterion.

## Confirmed format

| Property | F108 USB value |
| --- | ---: |
| Macro slots | 100 |
| Directory | 400 bytes, four bytes per slot |
| Unused slot | `FF FF FF FF` |
| Data block | 8-byte header + four bytes per event |
| Format ceiling | 3,584 bytes |
| OEM USB safety check | `(macro_count + event_count) * 8 <= 2700` |
| Delay field | 16-bit little-endian |
| Minimum delay | 10 ms; lower values clamp to 10 |
| Maximum delay | 65,535 ms |
| Loop field evidence | 1–99 in OEM metadata |
| Payload trailer | `55 AA` |

USB transaction:

```text
04 19              ACK
04 15, byte 8=N    ACK
N x 64-byte bank   ACK after complete payload
04 02              ACK
```

## Safety invariant

`serialize_bank` validates every slot, event, HID usage, mouse button, delay, duplicate ID, duplicate slot, OEM safety score, padded size and packet count before returning a complete byte buffer.

`send_bank` calls this serializer before its first transport operation. Therefore an invalid bank sends zero packets.

## Stable references

Schema 4 assigns each persisted macro a stable hardware slot from 0–99. Rename and deletion do not renumber other macros. Key assignments continue to store a macro ID; immediately before a remap write the desktop resolves that ID to the persisted hardware slot and emits action type `06`.

The only exposed playback choice remains `Once`. Other universal playback concepts stay hidden because their F108 action-byte behavior has not been physically verified.

## Automated coverage

- directory offsets and unused-slot encoding
- key-down, key-up and delay event bytes
- sub-10 ms delay normalization
- `55 AA` payload trailer and 64-byte packet padding
- USB safety-limit rejection
- 16-bit delay rejection
- empty-bank clearing payload
- stable slots across rename and delete
- macro capability and unverified status metadata
- JavaScript syntax for editor, upload and key assignment
