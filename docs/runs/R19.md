# R19: Windows integration

Status: implementation in automated validation; physical Windows soak test pending. Not complete.

## Implemented

- Native tray icon with open, pause/resume effects, active-profile submenu, reconnect and exit.
- Active-profile selection is saved and restored on launch.
- Closing/minimizing to tray and start minimized, saved independently.
- Start with Windows is opt-in and uses the Tauri autostart plugin. Autostart includes `--minimized`.
- Single-instance guard reopens the existing app rather than competing for HID interfaces.
- Native Windows suspend/resume notifications via `PowerRegisterSuspendResumeNotification`.
- Suspend marks I/O unavailable, cancels the active transaction, stops streams and closes device handles. No new writes or rediscovery during sleep.
- Wake redetects/reopens the device, reconciles the active profile and resumes enabled effects unless the user explicitly paused them.
- Every discovery, initialization, health, stream and configuration context shares a suspension gate, including I/O that races notification delivery. Replaced effect workers and audio captures are joined before their replacements start.
- Sharing/resource-busy failures report that another application appears to be using the configuration interface. Permission errors remain distinct and are not claimed to prove another app is running.
- Incomplete LCD transfers, including final-apply failure, retain a warning. There is no automatic transfer retry/resume.

Profile fingerprints compare actual output values rather than profile IDs; identical cloned profiles do not cause redundant writes. Tray menu refresh is bounded to two seconds and only replaces the menu when its contents change. Live-frame coalescing and bounded diagnostic logs remain in use while the window is hidden.

## Exit gate

CI checks are not a days-long hardware test. Required on the user's Windows PC:

1. Enable/disable each background preference; verify persistence and startup with Windows.
2. Close/minimize/open repeatedly; verify one process and a visible tray icon.
3. Change profiles from the tray; compare USB traffic for identical profiles and lighting-only differences.
4. Pause/resume static/live/music effects; confirm no capture or streaming traffic while paused.
5. Sleep/wake repeatedly with USB and 2.4G, including sleep during an LCD upload. Check incomplete warnings and original onboard menus.
6. Open the OEM app while MechKeyMesh is running. Verify clear conflict reporting and recovery after it closes.
7. Run at least 72 hours, including hidden/minimized use, disconnect/reconnect and daily sleep/wake. Record uptime, resource use, failed frames, reconnect counts and any warnings.

Mark COMPLETE only after that gate passes. No keyboard or interactive Windows session is attached to the execution environment, so physical results are currently unavailable.
