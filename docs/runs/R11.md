# R11: Device settings

Status: software implementation complete; physical change/verify/restore run pending.

## Evidence gate

R11 was not implemented until the raw enums were resolved:

| Setting | Raw value |
| --- | --- |
| Sleep | `0` Never, `1` 1 minute, `2` 5 minutes, `3` 30 minutes |
| Fn behavior | `0` Toggle, `1` Momentary |
| Key response | levels `1` through `5` |

F108 field offsets and the wired command are from static analysis of the exact OEM package:

- [`kidush/omarchy-aula-f108pro` protocol analysis](https://github.com/kidush/omarchy-aula-f108pro/blob/aa794b2367e0a66223198db3fe132a9505bc1833/docs/protocol.md)
- [`parsiya/f108-pro` HID protocol](https://github.com/parsiya/f108-pro/blob/f7782b02e254490d9c4ae063a8c27cae38be226f/ai-docs/hid-protocol.md)

Independent USB captures of the same `0C45:800A`, `04 17` protocol confirm the sleep sweep `0..3`, response sweep `1..5`, and their meanings:

- [`gavindi/Aula_L99_Linux` settings capture analysis](https://github.com/gavindi/Aula_L99_Linux/blob/78c2f02b91df5f2cac1dcd64a510076f877f3bb7/tools/aula_l99_hacky/re_notes/settings_write.md)

The capture is a closely related AULA model, not the F108. It corroborates raw enums and shared protocol positions; it does not replace the required F108 physical test.

## Wired block

```text
04 18                         ACK
04 17, byte 2=1, byte 8=1    ACK
64-byte settings data
04 02                         ACK
```

Data bytes:

| Offset | Meaning |
| ---: | --- |
| 0–1 | `00 01` tag |
| 2 | Disable Alt+Tab boolean |
| 3 | Disable Alt+F4 boolean |
| 4 | Disable Windows key boolean |
| 5 | Fn mode |
| 6 | Sleep enum |
| 7 | reserved zero |
| 8 | key response level |
| 62–63 | `AA 55` trailer |

The complete block is validated and built before the begin packet is sent.

## UI terminology

Key response is shown separately from approximate timing:

| Level | Label | Wired | 2.4G | Bluetooth |
| ---: | --- | --- | --- | --- |
| 1 | Fastest | 2–3 ms | 5–6 ms | 12–13 ms |
| 2 | Fast | 5–6 ms | 7–9 ms | 15–16 ms |
| 3 | Balanced | 8–9 ms | 10–12 ms | 18–19 ms |
| 4 | Stable | 13–14 ms | 15–17 ms | 23–24 ms |
| 5 | Maximum debounce | 17–18 ms | 19–21 ms | 27–28 ms |

The app states that the protocol is write-only and does not present saved desired state as a hardware readback.
