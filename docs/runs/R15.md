# R15: LCD media engine

R15 builds F108 LCD assets without opening a keyboard transport. Hardware upload is deliberately absent from this run.

## Fixed F108 contract

| Field | Value | Enforcement |
| --- | ---: | --- |
| Canvas | 240 × 135 | Every editable and compiled frame is validated |
| Pixel format | RGB565 little-endian | Conversion occurs only during final compilation |
| Animation header | 256 bytes | Byte 0 is frame count, bytes 1..N are 20 ms delay units, unused bytes are `FF` |
| Maximum frames | 141 | Construction, editing, optimization and compilation all reject frame 142 |
| Hardware page | 4096 bytes | The final immutable payload is padded to a complete page before validation |

## Import and processing

PNG, JPEG, GIF and WebP are decoded through the Rust image pipeline. Animated GIF and WebP timing is normalized to the F108's 20 ms header units. MP4, WebM and MOV use FFmpeg when that decoder is available on the host.

The presets are intentionally distinct:

- Smooth keeps 30 FPS and selects the portion that fits safely.
- Balanced uses 12 FPS to balance duration and motion.
- Full duration derives a lower frame rate from the clip duration so the complete clip fits in at most 141 frames.

All sources pass through fit/fill framing, high-quality resize, redundant-frame removal, motion-aware reduction where applicable, timing normalization, RGB565 conversion and final validation.

## Editor

The desktop LCD page exposes a timeline, per-frame preview and duration, duplicate, delete, reorder, text, brush, eraser, fit/fill import and undo/redo. Export writes a fully validated native F108 asset to disk. It never writes to the keyboard.

## Safety tests

The engine includes 10,000 property-generated planning cases plus exact native-format tests. Tests assert that the output is non-empty, contains no more than 141 frames, uses valid delay units and compiles to the exact header, content and page lengths. A dedicated regression test proves that frame 142 is rejected.

## Remaining validation

R15 is hardware-independent. R16 may consume only `F108Asset`, the immutable type produced after all R15 validation succeeds.
