## Required physical capture

Record firmware shown by the OEM tool or keyboard, hardware label, transport and OEM version separately. Capture USB input traffic passively with USBPcap/Wireshark while MechKeyMesh live effects and automatic profile switching are paused. Never install an input-blocking hook or write experimental knob/menu commands.

For each menu context (normal screen, Config menu, Volume), capture clockwise and anticlockwise rotate, press, Fn+rotate and Fn+press separately with timestamps. Record the interface/report ID, complete raw bytes, visible LCD change and Windows media event. An absence of host traffic is evidence of firmware-only handling, not proof that the knob is broken. Repeat in 2.4G mode. Stop the capture immediately after the controlled actions and avoid typing private information during capture.

For each menu setting, record before/after screenshots, host command traffic and observed behavior, then restore the original value. ACK alone is insufficient. Mark the run complete only after the user's firmware captures establish what is observable and the diagnostic output matches those observations.
