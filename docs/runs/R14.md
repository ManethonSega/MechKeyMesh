# R14: Music lighting

Status: software implementation complete; prolonged Windows audio and physical USB run pending.

## Pipeline

The `mechkeymesh-audio-engine` crate implements the shared pipeline:

```text
Windows render endpoint loopback
          ↓
48 kHz stereo to mono
          ↓
2048-sample Hann-window FFT, 1024-sample hop
          ↓
16 logarithmic bands plus bass, mids, treble and amplitude
          ↓
smoothing and release falloff
          ↓
R13 LiveRgbFrame and bounded USB transport
```

The capture thread uses WASAPI shared-mode loopback on the selected render endpoint. Shared-mode conversion requests a stable 48 kHz, 32-bit float stereo stream. Samples are reduced to mono in memory and are never stored or sent elsewhere.

Implementation references:

- [`wasapi-rs`, safe WASAPI bindings and loopback support](https://github.com/HEnquist/wasapi-rs)
- [`wasapi-rs` loopback initialization](https://docs.rs/wasapi/latest/wasapi/struct.AudioClient.html)
- [Microsoft loopback recording guidance](https://learn.microsoft.com/windows/win32/coreaudio/loopback-recording)

## Controls and modes

The application exposes:

- output device, including the current Windows default
- sensitivity
- smoothing
- release falloff
- independent bass, mids and treble weights
- off, solid or palette background
- master brightness
- four-color palette

Implemented render modes are spectrum, rainbow, reverse rainbow, amplitude and rhythm. All modes produce the same device-neutral `LiveRgbFrame` used by R13, so the existing one-frame latest-value queue provides USB backpressure.

Starting music lighting stops the ordinary live RGB renderer. Starting ordinary live RGB stops music lighting. This prevents two host renderers from competing for the keyboard stream.

## Capability boundary

Music lighting is advertised only by the F108 Pro USB connection variant. It is hidden on 2.4 GHz because that descriptor does not expose R13 live streaming. The feature targets the main key LED indices only. Side strips and the light bar above the arrow cluster remain outside this implementation.

## Automated coverage

Hardware-free tests verify:

- bass and treble sine waves produce the expected relative band response
- configured falloff prevents a one-frame collapse to zero
- every music mode emits a complete, LED-index-sorted frame
- configuration bounds reject unsafe or nonsensical values

The UI shows live band levels, analyzed frames, rendered frames and transport coalescing so long runs can be observed without attaching a debugger.

## Required physical run

1. On Windows, enumerate at least two output endpoints and select each one.
2. Start music lighting over F108 Pro USB and play bass-, mid- and treble-heavy material.
3. Exercise every mode and every control, including a silent input period.
4. Change the Windows default output endpoint and restart using System default.
5. Minimize and restore MechKeyMesh while audio continues.
6. Run for several hours while watching analysis, rendered, coalesced and failed counts.
7. Confirm synchronization remains stable, CPU use remains bounded and the device stays connected.
8. Switch to 2.4 GHz and confirm Music disappears or rejects safely.
9. Stop MechKeyMesh and confirm no audio capture remains active.

Until this run is recorded, R14 is not physically verified.
