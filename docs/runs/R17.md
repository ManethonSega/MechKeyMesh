# R17: Profiles and automatic switching

R17 turns the previously independent configuration systems into complete desired-state profiles.

## Profile contents

Each profile owns or references:

- normal mappings
- Fn mappings
- hardware macro bank
- onboard RGB
- stored per-key RGB
- live RGB scene and active host mode
- music-lighting configuration and active host mode
- device settings
- optional validated R15 LCD asset

Creating a profile clones the active profile transactionally, including stable macro slots. The Default profile cannot be deleted.

## Application rules

The native Windows monitor resolves the foreground process every 500 ms. Rules are case-insensitive, support `*` wildcards, and are evaluated by descending priority. If no enabled rule matches, the Default profile is selected. The monitor remains native while the window is minimized.

## State diffing

The profile controller serializes each subsystem's desired state into a runtime fingerprint. On activation it compares every fingerprint with the last successfully applied value:

- unchanged subsystems are recorded as skipped
- unavailable capabilities remain pending and are not falsely marked applied
- successful subsystems update their fingerprint
- failed subsystems retain their previous fingerprint and are retried after reconnect

Macro changes are applied before mappings so macro references never point at a stale bank. A reconnect clears applied fingerprints and reapplies the active profile. Optional LCD media is uploaded only when its validated asset identity changes and the wired Display capability is present.

## UI and diagnostics

The Profiles page supports clone, rename, delete, manual activation, automatic switching, rule priority, wildcard patterns and optional LCD assignment. The last application report separates changed, unchanged/unavailable and failed subsystems so unnecessary traffic is visible rather than inferred.

## Validation status

SQLite foreign keys, transactional cloning, rule matching and diff behavior are covered by automated tests and CI. Reliable foreground switching and USB traffic capture on physical hardware remain pending in this environment.
